## 設定工作區 AI

在 Web 或 Desktop，由工作區 `owner` 或 `admin` 開啟 **AI 代理 → AI 設定**。這組設定提供對話優化使用，不會取代 AI 代理本身的執行時與模型設定。

1. 在**模型供應商**選擇供應商，填入相容 OpenAI 格式的 API 端點、模型 ID 與 API 金鑰。自架（llama.cpp）與自訂端點可以不使用金鑰。模型可自行輸入，不限於建議清單；無金鑰端點若由伺服器提供模型，也可留空。
2. 點選**檢測連線**。測試使用表單目前的值與固定短提示，不含使用者內容；測試不會儲存修改。
3. 在**模型配置**設定對話 AI 的提示詞與可選的**關閉思考**。選擇 skill 後會以其內容取代可編輯提示詞；選回無 skill 即可自行編輯。
4. 點選共用的**儲存**按鈕。切換頁籤會保留未儲存的編輯；離開前確認儲存按鈕旁沒有錯誤。

供應商與主機未變更時，金鑰欄留空會保留已存金鑰。更換供應商或主機後，需要金鑰的供應商必須重新輸入。已存金鑰只以遮蔽形式顯示，不會顯示完整值。

模型建議、類型、視覺能力與上下文／輸出上限來自隨版本附帶的目錄，供參考，不代表已即時確認帳號可用性。對話優化需要對話模型；非對話類型會顯示提醒。點選模型欄旁的參數按鈕，可以查看模型的類型、視覺能力與上限。填入金鑰後，模型清單會直接向供應商查詢，不送出提示詞，也不耗用 token。供應商無法回應時，改用內建建議，仍可自行輸入。

目前每個工作區只有一組配置與一個選用模型。建立、複製、刪除配置、自訂請求頭、新增模型，以及嵌入、重排序、決策模型配置仍停用，標示為**下一輪開放**。

目錄找不到模型時，類型會依名稱推測；無法辨識的名稱預設顯示為對話類型。這個標籤僅供參考，不能當作相容性驗證。

## 優化草稿

工作區 AI 可用後，聊天、任務評論、回覆、編輯評論，以及建立／快速建立任務的編輯器會提供**對話優化**。先輸入文字，並等待附件上傳完成。

對話框並列顯示原文與可編輯的結果。可以檢查、修改結果，或再次點選**優化**。聊天、評論與回覆中的**送出**會依原輸入框的流程，連同附件與收件對象傳送；編輯評論與建立任務中的**採用**只把結果放回編輯器，之後仍需儲存或建立。若不確認，使用標題列的關閉按鈕返回。

優化失敗會保留原文；重新優化失敗則保留先前結果。送出失敗時，對話框會保持開啟以便重試。提及、連結與程式碼受到保護，遺失受保護內容的結果會被拒絕；確認前仍應檢查文字。

### 傳送前優化

在**設定 → 偏好設定 → 評論與聊天**啟用**對話優化**，傳送聊天、評論與回覆前就會先開啟確認對話框。這是目前裝置的偏好設定，預設關閉。工作區 AI 不可用或草稿只有附件時，仍走一般傳送流程。關閉這項偏好設定，即可自行選擇何時優化。

### 哪些內容會傳給模型？

優化會將草稿與相關上下文傳給工作區設定的端點。草稿中的提及、連結與程式碼會替換成佔位符，但上下文**不做遮蔽**。上下文可能包含自己的聊天記錄，或任務標題、描述與近期評論／討論串回覆。限制與端點控制見[環境變數](/environment-variables)。

## 可選的決議指示

聊天、評論與回覆可選擇**核准執行**或**再議討論**，選取本身不會立即傳送。核准時才會顯示單代理／多代理執行方式；實際傳送訊息時才附加指示。

單代理核准會指定 `superpowers:executing-plans`，多代理核准指定 `superpowers:subagent-driven-development`；再議則要求 AI 代理暫不開始。這些是訊息中的指示，不是獨立的執行或權限機制。選回**請決定**即可傳送一般訊息。

## 自託管前提

管理部署的人需先設定固定的 `MULTICA_AI_SECRET_KEY`，才能儲存 AI 設定並使用優化。遺失或更換後，已存的 AI 金鑰將無法解密。這些功能不會退回伺服器的 `MULTICA_LLM_*` 設定。

端點必須能從 Multica 後端連線。私有位址與 localhost 預設被拒絕，需透過 `MULTICA_AI_ALLOW_CIDRS` 明確允許；允許範圍適用所有工作區擁有者，應盡量縮小。詳見[環境變數](/environment-variables)。可選的 `deploy/llama/` 套件以你提供的 GGUF 檔案執行獨立模型伺服器，不會自動下載模型。
