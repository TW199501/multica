## ワークスペース AI の設定

Web または Desktop で、ワークスペースの `owner` または `admin` がエージェント一覧から AI 設定を開きます。これは文章改善用の設定であり、エージェント自身のランタイムやモデル設定を置き換えません。

1. プロバイダーのタブで、プロバイダー、OpenAI 互換 API エンドポイント、モデル ID、API キーを入力します。セルフホスト（llama.cpp）とカスタムはキーなしでも利用できます。候補にないモデル ID も入力できます。キーなしのエンドポイントがモデルを提供する場合は空欄にもできます。
2. 接続をテストします。現在の入力値と固定の短いプロンプトを使い、ユーザーの内容は送りません。テストだけでは保存されません。
3. モデル用途のタブで会話 AI のプロンプトと、必要なら思考を無効にする設定を変更します。skill を選ぶとその内容がプロンプトの代わりになります。手動編集に戻るには skill の選択を解除します。
4. 共通の保存ボタンを押します。タブを切り替えても未保存の入力は保持されます。保存ボタン横のエラーを確認してください。

同じプロバイダーとホストなら、キーを空欄にすると保存済みキーを保持します。どちらかを変更した場合、キーが必須のプロバイダーでは再入力が必要です。保存済みキーはマスクして表示されます。

モデル候補、種類、画像対応、コンテキストと出力上限は同梱カタログの参考情報で、アカウントの利用可否をリアルタイムに確認した結果ではありません。文章改善にはチャットモデルが必要です。モデル欄の横にあるパラメーターボタンを押すと、モデルの種類、ビジョン対応、上限を確認できます。キーを入力すると、モデル一覧をプロバイダーから直接取得します。プロンプトは送信せず、トークンも消費しません。応答がない場合は同梱の候補を表示し、直接入力もできます。

現在はワークスペースごとに設定と選択モデルが一つずつです。設定の追加・複製・削除、カスタムヘッダー、モデル追加、埋め込み・再ランキング・意思決定用モデルの割り当ては無効で、今後の対応として表示されます。

カタログにないモデルは名前から種類を推測し、判別できなければチャットとして表示します。この表示は互換性の保証ではありません。

## 下書きの改善

ワークスペース AI が利用可能になると、チャット、コメント、返信、コメント編集、タスク作成・クイック作成で改善ボタンを使えます。文字を入力し、添付のアップロード完了を待ってください。

原文と編集可能な結果を比較し、修正または再生成します。送信用の入力欄では送信ボタンが通常の送信処理を行い、添付や宛先も引き継ぎます。コメント編集とタスク作成では採用ボタンが結果をエディターに戻すだけなので、別途保存・作成が必要です。確定しない場合はタイトルバーの閉じるボタンを使います。

失敗時は原文を保持し、再生成の失敗時は前の結果を残します。送信失敗時もダイアログを開いたまま再試行できます。メンション、リンク、コードの保護により、保護対象を失った結果は拒否されます。確定前に内容を確認してください。

### 送信前の改善

設定の環境設定にあるコメントとチャットで、送信前の改善を有効にできます。チャット、コメント、返信の送信前に確認画面が開きます。このデバイス設定は初期状態ではオフです。AI が利用できない場合や添付だけの下書きは通常どおり送信できます。オフに戻すと手動で改善を選べます。

草稿と関連する会話は設定したエンドポイントに送られます。草稿のメンション、リンク、コードはプレースホルダーに置換されますが、会話の背景情報は**マスクされません**。自分のチャット履歴やタスクのタイトル・説明・最近のコメント／スレッド返信を含む場合があります。制限は[環境変数](/environment-variables)を参照してください。

## 任意の決定指示

チャット、コメント、返信では、実行承認または継続協議を選べます。選択だけでは送信されません。承認時だけ単一／複数エージェントの実行方式が表示され、送信時に指示が追加されます。

単一エージェントは `superpowers:executing-plans`、複数は `superpowers:subagent-driven-development` を指定します。継続協議は開始を待つよう指示します。これはメッセージ内の指示であり、別の実行・権限機構ではありません。空の選択肢に戻すと通常のメッセージになります。

## セルフホストの前提

保存と改善には、運用者が安定した `MULTICA_AI_SECRET_KEY` を設定する必要があります。紛失・変更すると保存済みキーを復号できません。`MULTICA_LLM_*` へのフォールバックはありません。

エンドポイントは Multica バックエンドから接続可能である必要があります。localhost とプライベートアドレスは原則拒否され、`MULTICA_AI_ALLOW_CIDRS` で明示的に許可します。許可範囲は全ワークスペース所有者に適用されるため、狭く指定してください。[環境変数](/environment-variables)に詳細があります。任意の `deploy/llama/` は用意した GGUF ファイルで独立したサーバーを起動し、モデルはダウンロードしません。
